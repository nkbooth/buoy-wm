## What Went Well

1. **TDD discipline held for every story, without exception.** All `wm_core`-level logic across all 7 stories followed strict RED→GREEN. No story quietly skipped this.
2. **The Wayland/Dispatch/process-spawn carve-out (build+clippy+manual-review, no live compositor in-sandbox) was used consistently and never crept.** Nothing that could have been unit-tested got waved through under this exemption — each story's Dev Agent Record explicitly justifies the carve-out per task rather than applying it blanket.
3. **The two-pass review model (review → fix → focused re-review) caught things a single pass would have missed.** Stories 1.4 and 1.5 both needed a second, HIGH-severity-focused re-review before closing — and in 1.5's case, that second pass is what caught that the first fix attempt genuinely didn't work as intended.
4. **Explicit user check-ins on scope, not silent judgment calls, resolved ambiguity correctly.** Story 1.5 needed this twice — once when a functional-requirement gap was found before implementation started, once again when the fix's actual behavior diverged from what was disclosed. Both times, the team stopped and asked rather than either quietly deferring or quietly over-building.
5. **Front-loading HIGH-priority review scrutiny on the identified risk pattern worked.** By Story 1.7 — the story with the most structurally similar risk profile to 1.4/1.5 (reworking `do_action`'s Dispatch control flow, activating a dormant call path) — explicit upfront scrutiny on exactly that category caught nothing. Either the pattern was resolved by then, or review process maturity itself prevented the bug from being introduced. Team leans toward the latter: 1.7 didn't just get reviewed harder, it was *written* with the pattern already in mind (the Dev Agent Record shows deliberate call-site-by-call-site verification, e.g. Task 6.3's explicit re-read of both `raise_view` call sites).
6. **Deliberately-skipped work was documented, not silently dropped.** Story 1.5's Finding #3 (consolidating `PINNED_TERM_APP_ID` comparisons into a shared predicate) was evaluated and explicitly declined with reasoning recorded, rather than either force-applied or quietly ignored.

## What Didn't Go Well / What to Change

1. **Confirmed root-cause pattern: every story that touched `main.rs`'s Dispatch glue, or reused/modified a `wm_core` primitive with call sites outside the story's own scope (`raise_view`, `cycle_focus`, `do_action`), produced real bugs.** Stories that stayed within pure, freshly-authored `wm_core` logic (1.1, 1.3, 1.6) were clean. This is now a known, named risk category — not a hypothesis.
2. **Story 1.5's first fix attempt shipped with an undisclosed regression.** The mid-drafting fix for the render-order gap silently introduced a "focus gets permanently stuck" bug and left the real compositor z-order path unguarded, and this wasn't caught until code review — not before. **Action:** when a fix is made to a shared primitive mid-story (not from the original task breakdown), treat it with the same scrutiny as if it were a new story's TDD scope, not an incidental patch.
3. **A sub-agent spuriously invoked its own `taskplan` gate during Story 1.4's fix-up, creating 4 noise tasks in Taskwarrior.** Caught and corrected (future sub-agent prompts were told not to self-invoke taskplan), but it's a process hygiene gap worth naming so it doesn't recur in Epic 2's more IPC-surface-heavy work.
4. **`devpod ssh` transport broke mid-Story-1.7** ("wait: remote command exited without exit status") despite the devcontainer itself running fine; the team worked around it via direct `podman exec` rather than stopping. Not an epic blocker, but worth a quick sanity check before Epic 2 starts so it isn't a recurring tax on every dev session.
5. **Known, consciously-deferred gaps carried out of Epic 1** (documented in-story, not hidden):
   - No `wm_core::unregister_output` — a removed real output leaves a stale, permanently-registered `wm_core` output eligible for `active_output_id` selection forever after (Story 1.7, flagged as YAGNI/out-of-scope for now).
   - `WmCore::mark_terminal_spawned` / `claim_pinned_terminal_spawn` still carry unnecessary `#[allow(dead_code)]` markers post-1.7 (harmless, cosmetic only).

## Next Epic Preview: Epic 2 — Tag Manager & Status Bar

Epic 2 builds an IPC server plus two companion clients (fuzzel-driven tag picker, per-output status bar) on top of Epic 1's state model. Story 2.1's own acceptance criteria state explicitly: IPC mutation commands (`toggle-tag`, `create-tag`, `switch-tag`) apply "via the same `wm-core` functions exercised by Story 1.7's raw keybinds."

**This is a direct hit on the exact risk category named above** — Epic 2 is, by design, adding a *third* call site (IPC) onto `wm_core` primitives (`switch_tag`, `create_tag`, `cycle_tag`) that already have two call sites each (raw keybinds from Epic 1, plus whatever internal callers exist). The same class of bug that hit `raise_view`/`cycle_focus` in 1.4/1.5 is structurally available here.

### Recommended preparation / carry-forward actions for Epic 2

1. **Apply the Story 1.7 review model by default, not as a special case.** Any Epic 2 story adding a new call site onto an existing `wm_core` mutator (`switch_tag`, `create_tag`, `cycle_tag`, `toggle_view_tag`) gets HIGH-priority review scrutiny up front, matching what worked for 1.7.
2. **Keep the two-pass review discipline (review → fix → focused re-review) for any story touching IPC-to-`wm_core` wiring** — this is the new equivalent of Epic 1's `main.rs` Dispatch glue.
3. **Sanity-check `devpod ssh` before Epic 2 kicks off** so a broken transport doesn't silently eat dev time story after story.
4. **Reconfirm sub-agent prompts do not self-invoke `taskplan` or create ad hoc Taskwarrior tasks** — carry the Story 1.4 correction forward explicitly into Epic 2's story prompts.
5. **No epic-plan changes required.** Nothing discovered in Epic 1 invalidates Epic 2's scope or approach — Epic 2's design (reusing Epic 1's `wm_core` functions for IPC handlers) was explicitly anticipated in the epics document, not a surprise.
