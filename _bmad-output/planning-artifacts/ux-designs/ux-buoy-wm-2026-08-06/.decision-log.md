- Cross-cutting: single user (Nick), Fedora atomic host, ~95% single-monitor (laptop or 42" dock), occasional multi-monitor.

## Discovery decisions (coaching path)

- **Status-bar surface [ARCH DECISION — flag for architecture reconciliation]:** status-bar client does NOT render its own window/layer-surface. It pushes current-tag state to an existing bar tool (waybar) via a custom module (script/polling or signal-driven). Resolves the wlr-layer-shell gap. This changes `external-integrations.md` (adds waybar as an integration) and `components.md`'s status-bar interface description — needs to be reconciled back into architecture docs, not just UX.
- **Visual identity source:** inherit the `foot.ini` `[colors-dark]` palette + `JetBrainsMono Nerd Font` as the DESIGN.md token source — confirmed as Nick's authentic aesthetic (alpha 0.84, blur, bg #101216, fg #d6d9df, muted blue-gray ANSI set). `waybar/style.css` found in chezmoi is stock/unmodified boilerplate (generic red/white, references `hyprland/window`) — explicitly NOT used as a source.
- **Fuzzel fallback interaction:** if Story 2.2's spike finds fuzzel can't do checkbox-toggle-in-one-invocation, fall back to fuzzel's native multi-select (`--multi`) — pick the full desired tag set in one pass, replace membership wholesale on accept. (Primary path remains checkbox-toggle if the spike confirms it's supported.)
- **Error/state signaling:** dim + label pattern for both — bar: current-tag text dims/grays out with a small disconnect glyph on IPC-down; picker: fuzzel shows a literal rejection message row (e.g. "tag limit reached (64)") on cap-out rather than silently rejecting.
- **Concern scan confirmed:** dark-mode-only (no light variant), no motion/animation (consistent with NFR1's 50ms budget), keyboard-only input (no mouse needed for picker), no notifications beyond the bar itself, multi-monitor = independent per-output tag shown on each bar instance.
- **Picker placement (multi-monitor):** picker always opens on the currently-focused output — follows attention, no fixed home output.

## Key flows (confirmed)

- **Flow A — Tag a window:** Nick is deep in a floating terminal window, hits the assign-hotkey. Fuzzel opens on the focused output with the window's current tags checked. He toggles/adds a tag, hits Enter. Fuzzel closes; bar unaffected (window tag ≠ output tag).
- **Flow B — Switch tags:** Nick hits the switch-hotkey. Fuzzel opens showing the full tag registry. He selects one; that output's displayed tag changes immediately. Bar updates to the new tag; pinned zellij session becomes visible (lazily spawned if not already running).
