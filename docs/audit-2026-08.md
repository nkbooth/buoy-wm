# The August 2026 audit, closed

A private audit of `buoy-wm` ran 22 passes (ten code-quality, twelve
security) on 2026-08-20. Its consolidated plan is kept out of the
repository. This file records how each High and Medium finding was closed
at v1.0.0, so that an `audit finding X-NN` comment in the code resolves to a
row a reader can open. Low findings appear only where the code cites them.
`tests/audit.sh` holds this file to the tree.

In scope: 41 findings, 4 of them High.

Each close-out is one or more of: **fixed** with the commits that fixed it,
**roadmap** with the [`docs/ROADMAP.md`](ROADMAP.md) section that carries
what is left, or **accepted** with the entry below that says why it stays.
A note after the dash records anything a reader of the finding would
otherwise get wrong. Each acceptance names the entry of the private plan's
"won't fix" list it corresponds to, so the two records can be held together.

## Accepted

1. **The IPC server is not rebound if its accept loop ends.** The accept
   loop iterates `UnixListener::incoming()`, which never yields `None`, so
   the loop cannot end while the process runs. A failed *bind* at startup
   is reported on screen and repeated in the journal while the session
   lasts, which is the case that happens. Rebinding code for an unreachable
   path would be untested by construction. (plan §6 #25)
2. **There is no window-management-only mode.** The IPC socket is always
   bound. Its clients are the picker and the status bar, both part of the
   same package, and the pinned terminals it was feared to imply can be
   switched off on their own (`pinned_terminals = false`). Nothing asks for
   a mode without the socket, and it would be a second configuration to
   test. (plan §6 #26)
3. **No systemd socket activation and no `--socket-path` flag.** The
   socket's lifetime is the WM's own, started by the session supervisor
   rather than by a socket unit, so activation would add a second owner.
   The path is resolved from `XDG_RUNTIME_DIR` and the tests already inject
   it as a parameter, so the flag would serve no caller. (plan §6 #19)
4. **No `delete-tag` request, so a created tag is never reclaimed.** Tags
   are permanent by design (ADR-006), and removing one would break the
   dense tag index every view's tag set and every output's current tag
   rely on. The connection cap and the per-connection creation quota bound
   how fast the 64-tag registry can fill; the cap itself is a product limit
   documented to the user. (plan §6 #11)
5. **No `catch_unwind` around the Wayland event loop.** A panic there means
   the WM's view of river's state is no longer trustworthy, and carrying on
   would act on it. The panic reporter logs the message, tells the user on
   screen and lets the process end, so the session ends visibly instead of
   continuing wrong. The panicking calls that the input could reach were
   removed; the one `expect` left on that path is documented where it is. (plan §6 #27)
6. **Invalid TOML, or a wrong `[defaults]` value, still rejects the whole
   file.** A bad keybind, mousebind or input entry is skipped and reported
   while the rest of the file applies. A file that is not TOML has no
   entries to keep, and a wrong `[defaults]` value has no entry to drop:
   quietly using the built-in value instead would be the whole-file discard
   in miniature. The user is told, and the built-in config runs. (plan §6 #28)
7. **The compositor's proxy-holding records stay outside the coverage
   floor.** `compositor/manager.rs` and `compositor/seat.rs`, which hold
   the live river proxies, and `compositor/dispatch.rs`, which receives
   their events, are among the files exempt from the 95% floor
   (CONTRIBUTING.md, "The coverage floor"). Their decisions are pushed into `WmCore` and the
   pure helpers, which the floor gates. Splitting the records into
   proxy-free halves is not scheduled for 1.0: it costs about as much as
   the decomposition of the old `main.rs` did and buys tests of glue only
   river can drive. It is on the roadmap for when a feature next changes
   these files. This replaces the clause of entry 8 below that called this
   split the missing test tier. (plan §6 #29)
8. **No end-to-end test harness.** One would need a nested river plus a
   real launcher and a real status bar. CONTRIBUTING.md is right that being
   honest about that boundary beats pretending to cover it. The plan also
   said here that the missing tier was the seam tier of the test-seam work;
   entry 7 above supersedes that clause. (plan §6 #16)
9. **One bounded exception to the function-length lint.** The IPC
   connection handler carries `#[allow(clippy::too_many_lines)]`, two lines
   over the gate. Its read, dispatch and write sequence is one transaction,
   and each cut tried so far moved lines without moving a decision. The
   comment on it calls it debt, not a pattern. (plan §6 #30)
10. **No protocol version field on the wire.** ADR-007 chose no schema
    versioning, and the WM, the picker and the status bar ship in one
    package at one version. A per-message compatibility test holds the
    three to one shape on every push instead. (plan §6 #31)
11. **History prefixes in existing comments are left in place.** About 160
    `Story N`, 90 `Task N` and 30 "code review follow-up" prefixes predate
    the rule in CONTRIBUTING.md ("Comments say why, and cite rather than
    narrate"). The rule stops new ones; rewriting the old ones would churn
    most files for no change in meaning. (plan §6 #32)
